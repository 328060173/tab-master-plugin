# 历史功能 PRD

> Status: Draft · Author: product-manager · Date: 2026-06-29

## 1. 背景与目标

### 1.1 现状与痛点

当前「历史」标签页只是占位（显示"需要 chrome.history API，开发中"），但用户对历史的诉求其实包含两类：

1. **最近关闭的标签**：误关标签想快速找回、刚才看的页面想重新看
   - 这类数据我们**已经有**！`useTabManager.ts` 里的 `recentlyClosed` 已存储最近 20 条关闭记录
   - 无需任何新权限

2. **完整浏览历史**：几天前看过某个网站，忘了网址，想翻出来
   - 这类数据需要 `chrome.history` API + 用户授权
   - 数据量大、需要搜索/时间筛选

用户经常混淆两者：
- 「我刚才关的页面在哪」→ 最近关闭（高频、即时）
- 「我上周看的那个教程在哪」→ 浏览历史（低频、回溯）

### 1.2 目标

**渐进式双模式**：
- **未授权状态**（零权限）：利用现有 `recentlyClosed` 数据，做「最近关闭的标签」页面
- **已授权状态**（可选权限）：同时显示「最近关闭」+「完整浏览历史」
- 支持搜索、按时间分组、一键恢复
- 与现有搜索功能打通

### 1.3 成功指标

- 最近关闭：用户找回误关标签的操作路径从「右键→恢复标签」（Chrome 原生）或「Ctrl+Shift+T 多次」→ 侧边栏里一键恢复
- 打开「历史」标签页的用户中，80% 点击了某个历史项（说明内容有用）
- 完整历史授权转化率：≥ 30%（点击 CTA 的用户中同意授权的比例）

## 2. 用户场景与故事

### 2.1 用户画像

| 角色 | 场景 | 频率 | 痛点 |
|------|------|------|------|
| 办公族 | 开了20+标签，误关重要页面，想立刻找回 | 每天1-2次 | 用 Ctrl+Shift+T 要试好多次才找到 |
| 研究者 | 刚才看的某个文档很有用，想重新找到 | 每周3-5次 | 不记得网址，只记得标题里的几个字 |
| 健忘者 | 记得3天前看过某个教程，想翻出来 | 每周1次 | 翻 Chrome 原生历史要翻很久 |

### 2.2 User Story 列表

作为**办公族**，我想在侧边栏里看到「刚才关闭的标签」，以便**误关后立刻恢复**。

作为**研究者**，我想搜索最近关闭标签的标题，以便**快速定位刚才看的文档**。

作为**健忘者**，我想看到更久之前的浏览历史，以便**找回几天前看的内容**。

作为**隐私敏感用户**，我希望只在需要时才授权浏览历史权限，以便**保护我的隐私**。

### 2.3 关键路径

**误关找回**：
1. 用户误关标签页
2. 打开侧边栏 → 切换到「历史」标签
3. 看到第一条就是刚才关的 → 点击恢复

**搜索找回**：
1. 用户记得刚才看的页面标题里有「Vue3」
2. 打开侧边栏 → 切换到「历史」标签
3. 在搜索框输入「Vue3」→ 过滤出结果 → 点击恢复

## 3. 竞品参考

### 3.1 Chrome 原生历史

**位置**：`chrome://history/`、右键菜单「重新打开关闭的标签页」、快捷键 Ctrl+Shift+T

**优点**：
- 数据全（浏览历史 + 最近关闭）
- 支持搜索

**缺点**：
- 是单独页面，会打断当前工作流
- 最近关闭只在右键菜单显示最近8条，且无法搜索
- 时间分组太粗（今天/昨天/上周/更早）

### 3.2 Session Buddy

**核心功能**：
- 保存会话（窗口 + 标签集合）
- 恢复会话
- 显示最近关闭的标签

**优点**：
- 会话管理很强大
- 最近关闭支持搜索、按时间分组

**缺点**：
- UI 太复杂，学习成本高
- 权限要得太多

### 3.3 OneTab

**核心功能**：
- 把当前标签页都收起来，变成列表
- 之后可以一键恢复

**优点**：
- 简单直接
- 收起来的列表就是"历史关闭"的变体

**缺点**：
- 不是真正的历史，是手动触发的
- 没有搜索

### 3.4 我们的差异化

- 侧边栏内完成，不打断当前工作流 ✅
- **渐进式权限**：先用「最近关闭」（零权限），需要时再授权「完整历史」✅
- 与现有搜索、标签管理无缝集成 ✅
- 窄屏适配（300-450px）✅

## 4. 权限策略

### 4.1 为什么用 optional_permissions

- **不吓用户**：安装时不请求 history 权限，避免用户因隐私顾虑拒绝安装
- **商店审核友好**：减少强制权限，降低审核风险
- **信任建立**：用户先用上「最近关闭」，感受到价值后再授权完整历史
- **可逆**：用户可随时在 Chrome 设置中撤销权限，我们也提供关闭入口

### 4.2 权限机制（待实现核实）

> - `chrome.permissions.contains({ permissions: ["history"] })` 检测权限状态
> - `chrome.permissions.remove({ permissions: ["history"] })` 撤销权限

### 4.3 隐私说明

授权时向用户说明：
- 完整浏览历史仅用于本地展示，不会上传到任何服务器
- 可随时在设置中关闭完整历史功能

## 6. 数据模型

### 6.1 数据来源对比

| 数据类型 | 来源 | 权限 | 存储 | 数量限制 |
|---------|------|------|------|---------|
| 最近关闭 | `recentlyClosed` | 无需 | `chrome.storage.local` | 20 条 |
| 浏览历史 | `chrome.history` | 可选 | Chrome 原生，不额外存储 | 按需查询 |

### 6.2 实体定义

**ClosedTabItem**（已存在，无需修改）：
```typescript
interface ClosedTabItem {
  id: number           // 关闭时的标签ID（仅作标识，恢复时不用）
  title: string        // 标签标题
  url: string          // 页面URL
  domain: string       // 域名（用于显示和搜索）
  favIconUrl: string   // 图标URL
  closedAt: string     // 关闭时间（ISO字符串）
}
```

**HistoryItem**（浏览历史，新增）：
```typescript
interface HistoryItem {
  id: string           // Chrome 历史记录 ID
  title: string        // 页面标题
  url: string          // 页面URL
  domain: string       // 域名（用于显示和搜索）
  favIconUrl: string   // 图标URL
  lastVisitTime: number // 最近访问时间（毫秒时间戳）
  visitCount: number   // 访问次数
}
```

### 6.3 存储位置

- 已存在 `chrome.storage.local.recentlyClosed`
- 浏览历史不额外存储，实时从 `chrome.history` 查询

## 7. 接口契约

无需新接口，前后端复用现有能力：
- `restoreTab(url: string)` - 恢复标签
- `recentlyClosed` - 最近关闭数据
- `searchClosed` - 搜索最近关闭（已在 SearchResults 实现）

新增 Chrome API 调用（待核实）：
- `chrome.permissions.contains()` - 检测权限
- `chrome.permissions.request()` - 申请权限
- `chrome.permissions.remove()` - 撤销权限
- `chrome.history.search()` - 搜索浏览历史
- `chrome.history.deleteUrl()` - 删除单条历史

## 8. 性能/安全/兼容

### 8.1 性能预算

- 列表渲染：≤ 100ms（最近关闭 20 条，浏览历史 100 条）
- 搜索过滤：≤ 50ms（实时响应）
- 浏览历史查询：≤ 200ms（Chrome API 调用）
- 内存占用：≤ 5MB（历史数据很小）

### 8.2 安全

- 未授权时：零权限，安全
- 已授权时：
  - history 权限仅用于本地展示
  - 不把历史数据发送到任何后端
  - 提供撤销权限入口
- 遵循最小权限原则

### 8.3 兼容

- Chrome 88+（Manifest V3）
- Edge 88+
- 与现有暗色模式、字号、密度设置自动兼容

## 10. Non-Goals

本期不做：
- ❌ 会话保存/恢复（那是另一个功能）
- ❌ 历史数据导出
- ❌ 清空所有历史（只支持单条删除）

## 附录：时间分组规则

```javascript
function getTimeGroup(closedAt: string): 'today' | 'yesterday' | 'earlier' {
  const date = new Date(closedAt)
  const now = new Date()
  const diffMs = now.getTime() - date.getTime()
  const diffHours = diffMs / (1000 * 60 * 60)
  
  if (diffHours < 24 && now.getDate() === date.getDate()) {
    return 'today'
  } else if (diffHours < 48) {
    return 'yesterday'
  } else {
    return 'earlier'
  }
}
```

时间显示规则：
- 1分钟内："刚刚"
- 1小时内："N分钟前"
- 24小时内："N小时前"
- 昨天："昨天 HH:MM"
- 更早："MM-DD HH:MM"
