# 统一标记选择浮层 PRD

> Status: 草稿 · Author: PM · Date: 2026-07-01

## 1. 背景与目标

### 1.1 现状问题
当前项目有**三处标记入口**，但实现不统一：
- ① 卡片汉堡菜单「标记」→ 4列网格、蓝底选中、宽 `w-72`、无新建入口
- ② 右键菜单「添加标记」→ 同①（共用浮层）
- ③ 批量菜单「标记」子菜单 → 单列、紫圆点、宽 `w-40`、有独立新建对话框
- ④ `TagPicker.vue` 卡片内嵌选择器 → 同①但带顶部新建输入框

**用户痛点**：
- 交互风格不统一，用户困惑
- 代码重复，维护成本高
- 标记字数多（15字中文）时展示效果差
- 浮层在窄侧边栏中易遮挡

### 1.2 目标
- 统一四处入口为一个 `TagSelectPopover` 组件
- 优化长标记、多标记的展示
- 保证不遮挡、交互清晰
- 支持单选（单标签）和多选（批量标签）模式

### 1.3 非目标
- 不改动标记数据结构（仍用 `string[]`）
- 不改动存储逻辑（仍用 `chrome.storage.local`）
- 不添加标记颜色/图标等扩展功能

---

## 2. 统一组件方案

### 2.1 组件定位
**组件名**：`TagSelectPopover`（独立组件，替换现有四处实现）

### 2.2 Props 契约
```typescript
defineProps<{
  /** 浮层唯一 ID，用于 PopoverManager */
  id: string
  /** 当前标签的已选标记（单标签模式），或批量模式的公共标记（交集） */
  currentTags: string[]
  /** 所有可用标记 */
  allTags: string[]
  /** 模式：single=单标签勾选（可多选标记），batch=批量应用（给多个标签加/删标记） */
  mode: 'single' | 'batch'
  /** 批量模式下，是否显示「从所有标签移除」选项 */
  showRemoveFromAll?: boolean
  /** 定位锚点 DOM */
  anchor: HTMLElement
  /** 弹出位置，默认 'bottom-left' */
  placement?: 'bottom-left' | 'bottom-right' | 'top-left' | 'top-right'
}>()
```

### 2.3 Events 契约
```typescript
defineEmits<{
  /** 单标签模式：切换标记 */
  toggle: [tag: string]
  /** 批量模式：应用标记到所有选中标签 */
  apply: [tag: string]
  /** 批量模式：从所有选中标签移除标记 */
  remove: [tag: string]
  /** 新建标记 */
  create: [tag: string]
  /** 关闭浮层 */
  close: []
}>()
```

### 2.4 四处入口整合方案
| 入口 | 模式 | 说明 |
|------|------|------|
| 卡片汉堡菜单「标记」 | `single` | 打开 `TagSelectPopover`，锚点为按钮 |
| 右键菜单「添加标记」 | `single` | 打开 `TagSelectPopover`，锚点为鼠标位置 |
| 批量菜单「标记」子菜单 | `batch` | 打开 `TagSelectPopover`，锚点为菜单项 |
| `TagPicker` 卡片内嵌 | `single` | 替换为 `TagSelectPopover`，锚点为图标按钮 |

## 3. 交互设计

### 3.1 浮层尺寸
- **宽度**：`288px`（`w-72`，保持现有合理宽度）
- **最大高度**：`320px`（比现有 `240px` 更高，容纳更多标记）
- **最小高度**：`120px`（空状态时的高度）

### 3.2 标记展示策略
**根据数量自适应列数**：
- ≤ 5 个标记 → **单列列表**（宽 `100%`，类似批量菜单）
- 6 ~ 10 个标记 → **双列网格**（`grid-cols-2`）
- > 10 个标记 → **四列网格**（`grid-cols-4`，保持现有紧凑布局）

**长标记处理**：
- 每个标记 chip **最大宽度 `100%`**
- 文字 **截断 + Tooltip**（`:title="tag"`）
- 四列模式下 chip 居中对齐

### 3.3 选中态视觉统一
- **已选**：蓝底白字 `bg-blue-600 text-white border-blue-600`
- **未选**：灰边黑字 `border-gray-200 dark:border-gray-600 text-gray-600 dark:text-gray-300`
- **Hover**：蓝边 `hover:border-blue-400`
- 移除紫色圆点，统一为背景色选中

### 3.4 新建标记入口
**所有模式统一在浮层顶部**（参考 `TagPicker.vue` 现有设计）：
```
[+ 新增标记（最多15字）] [添加]
```
- 输入框 `maxlength="15"`
- 输入为空时「添加」按钮禁用
- 新建成功后自动选中该标记（单标签模式）
- 新建成功后保留输入框聚焦，便于连续新建

### 3.5 空状态
```
┌─────────────────┐
│  暂无标记       │
│  [+ 新建标记]   │
└─────────────────┘
```
- 居中显示文字
- 显示新建按钮（或顶部输入框，取决于空间）

### 3.6 批量模式差异
批量模式下，每个标记显示两个按钮：
- **「+ 应用」**：给所有选中标签添加此标记
- **「- 移除」**：从所有选中标签移除此标记
- 或用 **复选框** 方式（勾选表示要添加/移除）

→ **决定**：用「三态按钮」：
  - 空心：未应用到任何标签
  - 实心蓝色：已应用到所有标签
  - 半实心蓝色：应用到部分标签
  - 点击切换：未应用 → 全部应用 → 全部移除 → 未应用...

### 3.7 不遮挡策略
- 使用现有 `computePopoverPos` 自动翻转/ clamp
- `z-index`：`[85]`（介于右键菜单 `[110]` 和普通浮层 `[80]` 之间）
- 从锚点反向弹出（上方空间不够时向上弹）
- 横向越界自动 clamp 到视窗边缘

## 4. 信息架构与布局

### 4.1 完整布局
```
┌─────────────────────────────────────┐
│ [+ 新增标记____________] [添加]    │  ← 顶部新建区（始终显示）
├─────────────────────────────────────┤
│                                     │
│  [标记1] [标记2] [标记3] [标记4]    │  ← 标记选择区（自适应列数）
│  [标记5] [标记6] [标记7] [标记8]    │
│  ...                                │
│                                     │
│  (空状态：暂无标记)                  │
│                                     │
└─────────────────────────────────────┘
```

### 4.2 边界状态
- **达 15 个标记上限**：隐藏新建输入框，显示提示「已达 15 个标记上限」
- **输入 15 字时**：输入框自动截断，不再接受输入
- **重复标记**：输入重复名称时「添加」按钮禁用，或输入后提示已存在

- [ ] 四处入口都打开同一个 `TagSelectPopover` 组件

## 7. 风险与未决问题

### 7.1 已知风险
- 批量模式的三态按钮交互可能不够直观 → 可考虑改为复选框 + 底部「应用」按钮
- 从单列/双列切换到四列时布局跳动 → 保持固定四列，或平滑过渡动画

### 7.2 未决问题
- [ ] 批量模式是否需要「从所有标签移除」选项？（当前 `showRemoveFromAll` prop 预留）
- [ ] 是否支持标记排序/拖拽？（本期不做，放后续）
- [ ] 是否支持标记删除/重命名？（本期不做，放后续）
