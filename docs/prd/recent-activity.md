# 最近操作排序功能 PRD

> Status: Draft · Author: product-manager · Date: 2026-07-06

---

## 1. 背景与目标

### 1.1 现状与痛点
用户希望快速找到**最近操作过的标签**，但目前的排序方式只有：
- 按域名
- 打开时间正序
- 打开时间倒序

这些方式都无法满足"最新操作的标签在最上面"的核心诉求。当用户打开很多标签时，需要滚动查找刚用过的标签，效率低下。

### 1.2 数据基础确认
项目已有完整的 `lastAccessed` 数据采集：
- `TabItem.lastAccessed` 字段已定义（Chrome 121+ 原生支持，老版本由 background.ts 兜底）
- `useTabManager.onTabActivated` 已在用户切标签时实时更新 `tabs.value[nextIdx].lastAccessed = Date.now()`
- `background.ts` 持续采集并持久化到 `chrome.storage.local.tabLastAccessedMap`
- `useCleanup.ts` 已在消费这个字段做"未使用标签"检测

### 1.3 目标
- 让用户能快速定位最近操作过的标签
- 不影响现有功能（按域名分组、稍后处理、历史页等）
- 保持代码鲁棒性和可维护性

### 1.4 非目标
- 不新增独立的导航 tab（不做方案 1）
- 不改变固定标签的显示逻辑（PinnedBar 保持独立）
- 不做视觉指示器（小圆点等，MVP 阶段只做纯排序）

## 2. 候选方案对比

| 维度 | 方案 1：新增「最近操作」tab | 方案 2：首页可折叠区域 | 方案 3：排序选项新增「按最新操作时间」 |
|------|----------------------------|-----------------------|--------------------------------------|
| 用户体验 | ❌ 割裂感：用户需要切换 tab 才能用 | ⚠️ 增加首页复杂度，折叠后容易被忽略 | ✅ 自然：用户已习惯用排序下拉切换 |
| 信息架构 | ❌ 破坏现有 4-tab 架构（首页/稍后/分组/历史） | ⚠️ 重复展示同一批标签，数据一致性风险 | ✅ 复用现有排序体系，架构清晰 |
| 实现成本 | ❌ 高：新增 ErrorBoundary、视图逻辑、联动代码 | ⚠️ 中：新增折叠区域、状态管理 | ✅ 低：只需改 `sortUtils.ts` + `AppToolbar.vue` + `sidepanel.vue` |
| 对现有功能影响 | ❌ 大：需要处理与首页的关系、批量操作联动 | ⚠️ 中：需要处理与现有首页标签列表的关系 | ✅ 小：纯排序逻辑，不影响其他功能 |
| 鲁棒性 | ❌ 低：新增大量代码，出错概率高 | ⚠️ 中：新增状态管理，可能出问题 | ✅ 高：复用现有成熟的排序框架 |
| 可扩展性 | ⚠️ 中：后续想加视觉指示器相对容易 | ⚠️ 中：区域内可以加更多功能 | ✅ 高：排序逻辑稳定，后续可加视觉指示器 |

### 2.1 推荐方案：方案 3（排序选项新增）

**核心理由**：
1. **用户体验最优**：用户已形成"用排序下拉改变标签顺序"的心智，无需学习成本
2. **实现成本最低**：只需改 3 个文件，复用现有排序体系
3. **影响范围最小**：纯排序逻辑，不影响按域名分组、稍后处理、历史页等其他功能
4. **鲁棒性最高**：在现有成熟框架上迭代，出错概率低

## 3. UX 细节设计

### 3.1 排序命名
- **新选项名称**：「按访问时间」
- **理由**：
  - 与现有「按域名」「时间正序」「时间倒序」风格一致（都是 4 个字）
  - 「访问时间」比「最新操作时间」更简洁
  - 「访问」比「操作」更准确（我们只监听 `onTabActivated`，即切到该标签）
- **最终排序选项顺序**：
  1. 按域名
  2. **按访问时间**（新增，放第二位，优先级高）
  3. 打开时间正序
  4. 打开时间倒序

### 3.2 视觉指示器
- **MVP 阶段**：不做视觉指示器（小圆点等）
- **理由**：纯排序已满足核心诉求，视觉指示器会增加复杂度，后续可根据用户反馈再加

### 3.3 默认排序
- **保持现状**：默认排序仍为「按域名」
- **理由**：
  - 「按域名」是用户已习惯的默认排序
  - 改变默认排序可能让老用户困惑
  - 用户可手动切换到「按访问时间」，设置会持久化

### 3.4 "操作"的定义
- **范围**：仅包含「切换到该标签」（`onTabActivated`）
- **不包含**：新建/关闭/固定/静音等操作
- **理由**：
  - 用户说的"最新操作"实际就是"最近访问过"
  - `lastAccessed` 字段语义就是"最后访问时间"
  - 其他操作不代表用户会再次访问该标签

### 3.5 兜底策略
- **数据缺失时**：`lastAccessed` 不存在或为 0 时，降级用 `openedAt`（打开时间）
- **刚打开扩展时**：所有标签都没触发过 `onTabActivated`，按 `openedAt` 倒序排序
- **跨窗口标签**：`onTabActivated` 只监听当前窗口，其他窗口的 `lastAccessed` 可能旧——这是合理的，用户更关心当前窗口的操作

## 4. 边界场景处理

### 4.1 刚打开扩展，还没切过任何标签
- **表现**：所有标签的 `lastAccessed` 都是初始值（从 Chrome 原生获取或 background.ts 兜底）
- **处理**：按 `lastAccessed` 倒序，缺失则降级用 `openedAt` 倒序

### 4.2 跨窗口标签
- **表现**：其他窗口的标签 `lastAccessed` 可能不是最新的
- **处理**：保持现状，只在 `onTabActivated` 时更新当前窗口标签的 `lastAccessed`——用户更关心当前窗口的操作

### 4.3 固定标签
- **表现**：固定标签在 PinnedBar 单独显示，不参与主列表排序
- **处理**：保持现状——排序只适用于非固定标签，PinnedBar 保持原有顺序

### 4.4 Chrome < 121（不支持原生 lastAccessed）
- **表现**：`chrome.tabs.Tab.lastAccessed` 不存在
- **处理**：已由 `background.ts` 兜底采集，无需额外处理

### 4.5 树形视图
- **表现**：树形视图下排序不可用（现有逻辑）
- **处理**：保持现状——树形视图下排序按钮灰显，提示"树形视图下排序不可用"

- ✅ 历史页（独立 tab，与首页排序无关）

- ✅ 聚焦模式（独立状态，与排序无关）
- ✅ 标记功能（排序不影响标记显示）

## 6. 验收标准

### 6.1 功能验收
- [ ] 排序下拉里有「按访问时间」选项，顺序为：按域名 → 按访问时间 → 打开时间正序 → 打开时间倒序
- [ ] 选择「按访问时间」后，标签按 `lastAccessed` 倒序排列（最新访问的在最上面）
- [ ] 切标签时（`onTabActivated`），该标签自动升到列表顶部
- [ ] `lastAccessed` 缺失时，降级用 `openedAt` 倒序
- [ ] 固定标签不参与排序，保持在 PinnedBar 原有位置
- [ ] 树形视图下排序按钮灰显，提示"树形视图下排序不可用"
- [ ] 排序选择持久化（刷新扩展/重启浏览器后保持上次选择）

### 6.2 兼容性验收
- [ ] Chrome 121+（原生 `lastAccessed`）正常工作
- [ ] Chrome < 121（background.ts 兜底）正常工作
- [ ] Edge 浏览器正常工作
- [ ] Windows/macOS 都正常工作

### 6.3 鲁棒性验收
- [ ] 排序切换时不报错，不触发 ErrorBoundary
- [ ] 大量标签（>100 个）时排序流畅，无明显卡顿
- [ ] 快速切标签时排序正确更新，无 race condition

## 7. Non-Goals（明确不做）

1. ❌ 不新增独立的「最近操作」导航 tab
2. ❌ 不在首页新增可折叠区域
3. ❌ MVP 阶段不做视觉指示器（小圆点等）
4. ❌ 不改变默认排序（仍为「按域名」）
5. ❌ 不监听新建/关闭/固定/静音等操作来更新排序
6. ❌ 不处理跨窗口标签的 `lastAccessed` 同步

---

## 8. 风险与未决问题

### 8.1 已知风险
- **风险**：用户可能期望"操作"包含新建/固定等，但我们只监听 `onTabActivated`
  - **缓解**：命名用「按访问时间」而非「按最新操作时间」，明确语义
- **风险**：刚打开扩展时，所有标签的 `lastAccessed` 可能都是旧的
  - **缓解**：降级用 `openedAt` 倒序，用户切几个标签后就正常了

### 8.2 未决问题（后续迭代）
- 是否需要给最近 N 分钟内访问的标签加视觉指示器（小圆点）？
- 是否需要把「按访问时间」设为默认排序？（需要数据支撑）
- 是否需要监听更多操作（如刷新、滚动）来更新 `lastAccessed`？

---

## 9. 后续迭代方向（可选）

1. **视觉指示器**：给最近 5/15/30 分钟内访问的标签加小圆点，让用户一眼识别
2. **默认排序优化**：根据用户数据，考虑是否把「按访问时间」设为默认
3. **更丰富的操作定义**：监听刷新、滚动等操作，更准确地判断用户"最近操作"
4. **跨窗口同步**：在 background.ts 监听所有窗口的 `onTabActivated`，同步 `lastAccessed`
