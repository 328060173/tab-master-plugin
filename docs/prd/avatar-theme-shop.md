# 积分商城：头像 / 头像框 / 插件主题

> Status: Draft · Author: plugs-pm · Date: 2026-07-17 · Feature slug: `avatar-theme-shop`

---

## 0. TL;DR（给用户拍板用，先看这里）

**一句话方案**：后端建一套「装扮商品 + 拥有记录 + 当前启用」的通用表，插件/官网共享；插件侧通过 CSS 变量注入 + 预设头像/头像框组件实现"装扮即所见"；MVP 只做**积分兑换**，人民币购买**跳官网支付页**（不在插件内嵌支付）。

**核心结论**：
1. 三类商品**独立 SKU**（avatar 头像 / frame 头像框 / theme 插件主题），不做"套装绑定"。每类同时只能启用 1 个。
2. 同一商品可同时挂 `pointsPrice` 和 `cashPrice`；**积分够 → 直接兑换**，**积分不够 → 跳官网 /shop 用人民币买**（或买积分包，二选一，推荐前者）。
3. 主题 = 一组 CSS 变量 + 可选背景图 URL + 可选容器边框样式。MVP 不做"自由组合"，只做"整包预设"。
4. 头像来源：MVP 只用**预设头像库**（后端托管），不开放上传（审核/存储成本高，决策点 7.6）。
5. 主题适配机制：在 `:root` 上挂 `--tm-skin-*` 变量（主色/背景图/边框圆角等 3-5 个高感知点），现有 Tailwind `dark:` 类**零改动**；没启用主题 = 现状不变。
6. 资源全走后端 CDN URL 按需加载，**不打包进扩展**（守带宽红线）；单图 ≤ 50KB，主题以 CSS 渐变/纯色为主、图片为可选增强。
7. 积分获取渠道 MVP **不扩充**，仍只靠签到（10 分/天）。商品定价锚定签到周期（如 30/90/180 天）。决策点 7.8。

**给用户的决策点清单（带 PM 推荐）**见 §7。

## 1. 背景与目标

### 1.1 现状/痛点

- **积分体系已就绪但无出口**：后端 `/customer/my` 返回 `points`、`/customer/checkin` 送 10 分/天、`/customer/points/bill` 流水已通；插件 options 页已显积分+签到。**但积分目前只能攒不能花**——用户签到动力会快速衰减（"攒了能干嘛？"）。
- **插件外观无个性化**：仅浅色/深色/跟随系统三档，无主色调/背景/头像差异。同类效率工具（Workona、Edge 主题、Notion）都有皮肤/个性化，用户对"我的工具长得像我"有期待。
- **账号体系缺"软价值"**：已登录卡片只有邮箱+积分两个数字，缺乏身份感/成就感。这是低成本提升 7 日留存与登录转化率的抓手。
- **变现渠道单一**：当前只有广告+捐助，缺一个"小额高频"的付费场景。装扮商城天然适合（QQ 秀验证过的模型）。

### 1.2 目标

**本期（MVP）解决**：
1. 给积分一个**消费出口**，让签到有持续动力（积分→装扮→身份展示）。
2. 给已登录用户一个**轻量身份表达**（头像+头像框+主题色），提升登录转化与留存。
3. 跑通"商品-拥有-启用-展示"的**通用装扮链路**，后续加新装扮类型零改动架构。

**本期不解决**（见 §9 Non-Goals）：支付在插件内闭环、用户上传头像、自由组合主题、复杂套装/折扣/限时活动运营。

### 1.3 成功指标

- 签到 7 日留存率较上线前提升 ≥ 15%（积分有了消费出口）。
- 已登录用户中，启用过至少 1 个装扮的比例 ≥ 40%（30 天内）。
- 商城页首屏渲染 ≤ 500ms（受 CDN 图片加载影响，骨架屏兜底）。
- 主题切换后插件 UI 生效延迟 ≤ 200ms（CSS 变量写入到视觉更新）。
- 零回归：未启用主题/未登录用户，插件外观与上线前 100% 一致。

## 2. 用户场景与故事

### 2.1 用户画像

| 画像 | 频次 | 触发情境 | 核心诉求 |
|---|---|---|---|
| **攒分小白** | 每日签到 | 看到 options 积分涨 | "积分能换啥？" → 进商城挑便宜的换 |
| **个性化党** | 偶尔换主题 | 用腻了默认蓝 | "想让插件长得不一样" → 换主题色/背景 |
| **身份党** | 偶尔换头像框 | 想被群友/同事看到 | "我签到 100 天了" → 戴上"百日签到"专属框 |
| **付费急党** | 看中贵商品 | 积分不够 | "现在就要" → 跳官网花钱买 |

### 2.2 User Story

- **US-1**：作为签到用户，我想在 options 看到积分旁边有「去商城」入口，以便知道积分能换什么。
- **US-2**：作为用户，我想在商城浏览头像/头像框/主题三类商品并看到价格，以便挑选。
- **US-3**：作为积分够的用户，我想一键兑换并自动启用，以便立刻看到效果。
- **US-4**：作为积分不够的用户，我想看到"还差 X 分 / 或去官网购买"，以便决定攒分还是花钱。
- **US-5**：作为已拥有多个装扮的用户，我想在"我的装扮"里切换当前启用的，以便随时换风格。
- **US-6**：作为换主题的用户，我想切换后插件立即变样，以便确认效果符合预期。
- **US-7**：作为不喜欢主题的用户，我想一键恢复默认，以便回到原样。

### 2.3 关键路径（最长旅程）

```
用户打开 options → 看到积分旁「商城」入口 → 进入商城页（分 3 个 tab：头像/头像框/主题）
  → 浏览商品卡片（预览图 + 名称 + 积分价 + 人民币价 + 拥有/未拥有标记）
    → 积分够 → 点「积分兑换」→ 二次确认 → 扣分成功 → 自动启用 → toast「已兑换并启用」
    → 积分不够 → 点「去官网购买」→ chrome.tabs.create 官网 /shop?sku=xxx
        → 官网完成支付 → 拥有记录回写 → 用户回到插件商城点「启用」
  → 在 options「我的装扮」切换当前启用 → CSS 变量立即更新 → 插件 UI 变样
```

## 3. 竞品参考

| 产品 | 装扮维度 | 获取方式 | 应用机制 | 学什么 / 避什么 |
|---|---|---|---|---|
| **QQ 秀 / QQ 头像框** | 头像 + 头像框 + 聊天背景 + 套装 | 积分（QQ 币）+ 人民币 + 活动赠送 | 客户端读配置渲染 | 学：套装/限时运营模型成熟；**避**：过度运营（限时/折扣/抽卡）MVP 不做 |
| **Workona 主题** | 工作区背景图 + 主题色 | 免费 + Pro 付费 | CSS 变量注入 | 学：主题=CSS 变量；**避**：Workona 主题绑工作区，我们全局即可 |
| **VS Code 主题** | 颜色主题 + 文件图标主题 + 产品图标主题（三维独立） | 扩展市场免费/付费 | settings 驱动全局 | 学：三类**独立 SKU**、每类单选；**避**：VS Code 主题文件极复杂，我们只覆盖 3-5 个变量 |
| **Edge / Chrome 主题** | 整套配色 + 背景图 | 商店免费/付费 | 浏览器层注入 | 学：整包预设、一键切换；**避**：我们是插件内主题，不能动浏览器 chrome |

**差异化**：
- **积分驱动**为主（签到→积分→装扮），区别于 QQ/VS Code 的纯付费/免费模型，更贴合"轻量效率工具"调性。
- **三类独立 SKU + 每类单选**（学 VS Code），简单可控，避免套装耦合。
- **主题只动 3-5 个高感知点**（主色/背景图/边框圆角），不做全量配色重构，零回归风险。


### 4.4 主题注入机制（关键适配工作）

**现有机制**（不动）：`useSettings.ts` 的 `applyTheme()` 在 `:root` 加 `theme-light/theme-dark` + Tailwind `dark` class；所有组件用 Tailwind `dark:` 变体。**项目无 `--color-primary` 这类 CSS 变量**，颜色全部 Tailwind 类硬编码。

**新增机制**（叠加，不替换）：新增 composable `useSkin.ts`，在 `:root.style` 上写入一组 `--tm-skin-*` 变量。变量只被**少数高感知点**消费：

| CSS 变量 | 默认值（未启用主题） | 消费点 |
|---|---|---|
| `--tm-skin-primary` | `#2563eb`（Tailwind blue-600） | options 主按钮、商城主按钮、sidepanel 当前选中态边框 |
| `--tm-skin-accent-bg` | `transparent` | options/sidepanel 顶部 header 背景叠加层 |
| `--tm-skin-page-bg-image` | `none` | body `::before` 伪元素背景图（透明度 0.06，不喧宾夺主） |
| `--tm-skin-card-radius` | `0.5rem` | 卡片圆角（侧边栏标签卡 / options 卡片） |
| `--tm-skin-card-border` | `1px solid rgba(229,231,235,1)` | 卡片边框 |

**适配工作量**：
- 新增 `composables/useSkin.ts`：读 storage 当前主题配置 → `document.documentElement.style.setProperty` 写变量。约 60 行。
- 新增 `assets/skin-overlay.css`：定义 body `::before` 背景图层 + 几个 `.skin-aware` 工具类（主按钮、选中态边框、卡片）引用变量。约 30 行。
- 改动点（grep 替换，每处 1 行）：options.vue 主按钮、sidepanel.vue Header 选中态、TabTileItem 卡片边框圆角——把硬编码改为 `var(--tm-skin-xxx, <原值>)` 形式，**带 fallback**，未启用主题时视觉零变化。
- 没启用主题 = 变量取 fallback = 与现状 100% 一致。**这是零回归的关键**。

### 4.5 边界状态

| 场景 | 系统行为 |
|---|---|
| 未登录进商城 | 顶部 banner「登录后可兑换装扮」+ 商品可见但按钮置灰，点按钮弹登录引导（复用 LoginDialog） |
| 商品图加载中 | 骨架屏（gray-100 占位 + pulse 动画） |
| 商品图加载失败 | 默认占位图 + 小字「预览加载失败」 |
| 积分兑换网络失败 | toast「网络不可用，请稍后再试」，积分不扣（后端事务保证） |
| 后端返回积分不足 | toast「积分不足，还差 X 分」，按钮自动切「去官网购买」态 |
| 主题切换后某变量解析失败 | 该变量回退默认值（CSS fallback 机制），不阻断其他变量 |
| 用户在多设备切换主题 | A 设备启用 → 写后端；B 设备打开 → 拉取当前启用 → 同步（依赖 /customer/my 返回 currentSkin） |
| CDN 图片域名不可达 | 主题仍可用（只是背景图不显示），主色/边框仍生效 |
| 商城页 1 万个商品 | MVP 不分页（商品总量预计 < 100），后续加分页/虚拟滚动（Non-Goal） |

### 4.6 引导/教育

**首次进商城**：顶部固定一行问号说明条（可折叠），内容：
> 💡 装扮商城：用签到积攒的积分兑换头像、头像框和插件主题。积分不够也可在官网购买。装扮在所有登录设备同步。

**问号 `?` 说明**（点击展开）三个：
1. **积分怎么来**：当前仅每日签到（10 分/天），后续会加更多渠道。
2. **买了能用多久**：MVP 为永久拥有（无过期）。后续可能推出限时装扮（Non-Goal）。
3. **装扮同步到哪里**：插件 options / sidepanel 顶部 / 官网个人中心 /my，登录态共享。

### 4.7 可感知设计检查清单（对照行为准则 §6）

| 操作 | 事前文案/图标 | 事中反馈 | 事后提示 | 撤销路径 |
|---|---|---|---|---|
| 进商城 | options「商城」按钮（🛍 图标 + "商城"） | 新 tab 打开 + 骨架屏 | 商品列表渲染 | 关闭 tab |
| 兑换商品 | 按钮文案「积分兑换 100」明示扣分 | 按钮 loading + 二次确认弹窗「扣除 100 积分，**不可退回**」 | toast「已兑换并启用 ✓」 | 在「我的装扮」切换其他或恢复默认（积分不退） |
| 积分不够 | 按钮「去官网购买 ¥6」+ 小字"还差 180 积分" | 跳转新 tab | 官网提示支付结果 | - |
| 启用装扮 | 按钮「启用」 | 按钮 loading | toast「已启用：极简蓝」+ UI 立即变样 | 启用其他 / 恢复默认 |
| 恢复默认 | 「恢复全部默认」红色文字按钮 | 二次确认「将恢复默认头像/头像框/主题」 | toast「已恢复默认」 | 重新启用 |
| 主题未生效 | - | - | toast「主题已启用，部分页面需刷新扩展生效」+ 引导去 chrome://extensions 刷新 | - |
| 未登录点兑换 | 按钮置灰 + tooltip「登录后可兑换」 | 点按钮弹 LoginDialog | 登录成功后回商城 | - |

**检验三问**：兑换前知道扣多少分（按钮+确认弹窗明示）✓；兑换中知道在进行（loading）✓；兑换后知道结果（toast + UI 变样）✓。

### 4.8 数据一致性（对照行为准则 §7）

- **派生数据来源**：当前积分 = 后端 `/customer/my` 返回，**不**从本地 storage 派生（避免本地篡改）。兑换成功后**以后端返回的新 points 为准**刷新 UI，不本地 +10/-10 猜算。
- **拥有记录**：以后端 `GET /shop/my-items` 为准，本地 storage 仅缓存当前启用 ID（加速首屏），每次进商城强制拉取后端覆盖缓存。
- **当前启用**：以后端 `currentSkin`（在 /customer/my 返回）为单一真相源；本地 `useSkin` 启动时从 /customer/my 读，切换时先调 `POST /shop/activate` 成功再更新本地 + 写 CSS 变量。**不允许本地单方面改启用态**。
- **chrome 事件兜底**：不涉及 tabs 事件；涉及 `storage.onChanged`——若用户在另一设备改了启用态，本设备 storage 同步触发 useSkin 重读（已登录态 storage 共享机制沿用 useAuth）。
- **跨窗口**：装扮是账号级配置，与浏览器窗口/标签无关，不存在跨窗口污染。

## 6. 接口契约（前后端协作，由 api-backend 在 ouu-server-api 仓实现）

> 沿用现有约定：baseURL `https://api.ouu365.com/ouu-api`；请求头 `platform=1 / appCode=app_1001 / versionCode=1` + `Authorization: Bearer {token}`；响应若依 `R<T>` 包装。

### 6.1 接口列表

| 接口 | 方法 | 路径 | 授权 | 说明 |
|---|---|---|---|---|
| 商品列表 | GET | `/shop/skus` | 否（已登录可同时返回拥有状态） | 按 type 过滤，返回商品+是否拥有 |
| 我的装扮 | GET | `/shop/my-items` | 是 | 返回已拥有商品 + 当前启用 |
| 积分兑换 | POST | `/shop/redeem` | 是 | 扣分+写拥有+自动启用 |
| 设置当前启用 | POST | `/shop/activate` | 是 | 切换某类商品的当前启用 |
| 恢复默认 | POST | `/shop/reset` | 是 | 清空当前启用（全部回默认） |

> 支付购买不在本契约内——插件只跳转官网 `/shop?sku=xxx`，官网调后端下单+支付回调接口（由 web-pm/api-backend 另出契约）。

### 6.2 商品列表 `GET /shop/skus?type=1`

**Query**: `type` (1/2/3，可选，不传返回全部)

**Response**:
```json
{
  "code": 200, "msg": "success",
  "data": {
    "items": [
      {
        "skuId": "avatar-cat-01",
        "type": 1,
        "name": "橘猫",
        "previewUrl": "https://cdn.ouu365.com/skin/avatar-cat-01.webp",
        "pointsPrice": 100,
        "cashPrice": 0,
        "owned": false,
        "active": false,
        "config": null
      }
    ],
    "currentPoints": 320
  }
}
```
> 已登录时 `owned`/`active`/`currentPoints` 填实值；未登录时三个字段为 null。

### 6.3 我的装扮 `GET /shop/my-items`

**Response**:
```json
{
  "code": 200, "data": {
    "owned": [ { "skuId": "...", "type": 1, "name": "...", "previewUrl": "...", "config": null, "acquiredAt": "..." } ],
    "active": { "avatar": "avatar-cat-01", "frame": null, "theme": "theme-minimal-blue" },
    "activeConfig": {
      "avatar": { "url": "..." },
      "frame": null,
      "theme": { "primary": "#3b82f6", "pageBgImage": "url('...')", "cardRadius": "0.5rem", "cardBorder": "...", "accentBg": "..." }
    }
  }
}
```
> `activeConfig` 一次性返回当前启用商品的完整配置，避免前端再逐个查 sku。

### 6.4 积分兑换 `POST /shop/redeem`

**Request**: `{ "skuId": "theme-minimal-blue" }`

**后端事务**：① 校验商品上架 ② 校验未拥有 ③ 校验积分够 ④ 扣分写流水 ⑤ 写拥有记录 ⑥ 自动写启用（覆盖该 type 的 active 字段）→ 返回。

**Response（成功）**:
```json
{ "code": 200, "data": { "newPoints": 220, "active": { "theme": "theme-minimal-blue" }, "activeConfig": { "theme": {...} } } }
```

**错误码**：
- `40001` 商品不存在或已下架
- `40002` 已拥有该商品
- `40003` 积分不足（msg 带 `need`/`have`）
- `40004` 该商品不支持积分兑换（pointsPrice=0）

### 6.5 设置当前启用 `POST /shop/activate`

**Request**: `{ "type": 3, "skuId": "theme-warm-orange" }`
（`skuId` 为 null 表示清除该类启用，回默认）

**Response**: `{ "code": 200, "data": { "active": {...}, "activeConfig": {...} } }`

**校验**：skuId 非空时必须已拥有 + type 匹配。

### 6.6 恢复默认 `POST /shop/reset`

**Request**: `{ "types": [1,2,3] }`（可只重置某类）

**Response**: `{ "code": 200, "data": { "active": { "avatar": null, "frame": null, "theme": null } } }`

## 7. 给用户的决策点清单（带 PM 推荐）

### 7.1 支付是否 MVP 做？
**推荐：不在插件内嵌支付，MVP 跳官网。**
- 理由：插件内嵌支付涉及 CSP（MV3 严禁远程脚本）、第三方 SDK 集成、回调页处理，工作量等于一个独立项目。官网已有支付页基础设施预期（/donate /contact 都走官网），复用成本低。
- 影响：积分够的用户在插件内闭环体验好；积分不够的跳官网，体验稍断但可接受（QQ 秀也是客户端跳网页支付）。
- 备选：MVP 完全不做付费，只做积分兑换，等签到留存数据验证后再上付费。**若用户想最快上线，推荐此备选**。

### 7.2 主题打包 vs 自由组合？
**推荐：MVP 整包预设，不做自由组合。**
- 理由：自由组合（主色+背景+边框各选各的）UI 复杂度指数上升，且组合效果难预览。整包预设 = 一个 SKU 一个完整 config，开发/运营/用户认知都最简。
- 后续：可加"自定义主题"功能（Non-Goal），届时再开放组合。

### 7.3 头像来源？
**推荐：MVP 仅预设头像库（后端托管 20-30 个），不开放上传。**
- 理由：用户上传涉图片审核（合规风险）+ 对象存储成本 + 头像压缩/裁剪逻辑，工作量大。预设库足够覆盖个性化需求。
- 头像库内容建议：动物/几何图形/渐变色块/节日主题，风格统一轻量。

### 7.4 头像/头像框展示在哪？
**推荐**：
- options.vue 已登录卡片：邮箱左侧加 32px 圆形头像 + 头像框叠加（绝对定位）。
- sidepanel 顶部 Header 左侧：加 20px 小头像（无头像框，太挤），点击跳 options 个人信息。
- 官网 /my：头像 + 头像框 + 当前主题预览（web-pm 出页面）。
- **不展示**在 sidepanel 标签列表里（与标签数据无关，避免噪音）。

### 7.5 主题覆盖维度（CSS 变量数量）？
**推荐：MVP 只 5 个变量**（§4.4 表）：主色、背景叠加、背景图、卡片圆角、卡片边框。
- 理由：覆盖太多变量 = 要改太多 Tailwind 硬编码处 = 回归风险高。5 个变量已能让用户明显感知"换主题了"。
- 后续：根据用户反馈加变量（如字号、间距、按钮形状）。

### 7.6 积分获取渠道是否扩充？
**推荐：MVP 不扩充，仍只靠签到。**
- 理由：先验证"签到→积分→装扮"闭环是否成立。若签到留存提升达标，再扩渠道（如每日首次打开+2、连续 7 天+10、邀请新用户+50）。
- 定价锚定：最便宜头像 100 分 = 10 天签到；最贵主题 500 分 = 50 天签到。让用户觉得"攒一攒就能换到"。

### 7.7 商品过期/限时？
**推荐：MVP 全部永久拥有，不做限时。**
- 理由：限时运营（折扣/下架/倒计时）是运营复杂度大头，MVP 不碰。永久拥有也让用户更有"投入值"的感觉。

### 7.8 资源体积策略
**推荐**：
- 头像/头像框：WebP 格式，单图 ≤ 30KB（128x128 够用），pngquant 质量压到 70-85。
- 主题背景图：WebP，单图 ≤ 50KB，CSS `background-size: cover` + 透明度 0.06 叠加。
- 主题以**纯色/渐变**为主（CSS 变量直接表达，零图片），图片背景是少数主题的增强项。
- 全部走后端 CDN `cdn.ouu365.com`，**不打包进扩展**。扩展只存 skuId + config JSON（几 KB）。
- 守带宽红线：用户首次启用主题时才加载背景图（懒加载），未启用不下载。

### 7.9 官网购买页是否本期同步上线？
**推荐：若选 7.1 主推荐（跳官网支付），则官网 /shop 页需 web-pm 同步出 PRD。若选 7.1 备选（MVP 只积分），则官网 /shop 可延后，插件按钮"积分不够"时只显 toast「积分不足，多签到攒分吧」。**
- 跨线依赖：若走官网支付，需 web-pm 出 `/shop` 页 PRD + web-fe 实现 + api-backend 出下单/支付回调接口契约。这是协调点，建议 product-master 出协调计划。

## 8. 性能 / 安全 / 兼容

### 8.1 性能预算
- 商城页首屏渲染 ≤ 500ms（骨架屏兜底，图片懒加载）
- 商品图懒加载（IntersectionObserver，进入视口前 200px 加载）
- 主题切换生效 ≤ 200ms（CSS 变量写入到 paint）
- 主题 config 缓存命中时首屏 ≤ 50ms 应用变量（避免 FOUC 闪烁）
- 单个商品图 ≤ 50KB，商城页一次打开图片总量 ≤ 1MB（约 20 个商品）

### 8.2 安全
- **token 不出现在用户可见处**（守品牌红线，用户可见处只说"账号"）
- 兑换走后端事务，**前端绝不本地扣分**（防篡改）
- 商品 config 是后端可信源，前端只消费不生成；若 config 含非法 CSS（如 `javascript:` 伪协议），前端校验过滤后注入
- 背景图 URL 白名单：只允许 `cdn.ouu365.com` 域名（CSP `img-src` 限制）
- 禁用 v-html（装扮名/描述均文本渲染）
- 兑换接口防重放：后端按 (customer_id, sku_id) 唯一键兜底

### 8.3 兼容
- **目标矩阵**：Chrome 102+ / Edge 102+ × macOS / Windows（4 格必测）
- CSS 变量：Chrome 49+ 全支持，无兼容问题
- `document.documentElement.style.setProperty`：全支持
- 主题在浅色/深色模式下都要可用：主题 config 的颜色值需同时适配 `theme-light/theme-dark`——MVP 简化为"主题色不区分明暗，背景图在深色下透明度自动降为 0.04"（CSS 媒体查询处理）
- sidepanel 300-400px 窄宽下，商城入口在 options 不在 sidepanel，无窄宽适配问题

## 10. Non-Goals（本期明确不做）

- ❌ **插件内嵌支付**：不在插件内集成微信/支付宝 SDK，付费走官网
- ❌ **用户上传头像**：不开放上传，仅预设头像库
- ❌ **主题自由组合**：主色/背景/边框不可各选各的，只整包预设
- ❌ **限时/折扣/抽卡运营**：不做倒计时、限时下架、盲盒抽卡
- ❌ **套装绑定**：不卖"头像+头像框+主题"套装，三类独立
- ❌ **装扮赠送/交易**：用户间不可赠送/交易装扮
- ❌ **装扮过期机制**：MVP 全部永久拥有
- ❌ **积分获取渠道扩充**：不新增除签到外的积分渠道
- ❌ **主题覆盖全量 UI**：只覆盖 5 个 CSS 变量，不重构 Tailwind 配色体系
- ❌ **sidepanel 内嵌商城**：商城放新 tab，不在 sidepanel 窄宽里展示
- ❌ **商品分页/搜索**：MVP 商品总量 < 100，不分页不搜索
- ❌ **装扮分享到社交**：不做"分享我的装扮"功能

### 12.4 注意事项
- useSkin 单例模式（学 useTabManager / useAuth）
- 主题变量写入用 `document.documentElement.style.setProperty('--tm-skin-primary', value)`，**带 fallback**：`var(--tm-skin-primary, #2563eb)`
- 商城页是新 tab 页，走 Plasmo `tabs/` 约定，新增后必须 `rm -rf .plasmo build` 全新构建
- 头像/头像框图片懒加载（IntersectionObserver），不进首屏 critical path
- 所有新增页面/弹窗先包 ErrorBoundary（scope=shop / scope=my-skin）

- i18n key 同步加 zh-CN / en-US
- 商城页主色调跟随当前主题（自举：商城本身也消费 --tm-skin-primary）
