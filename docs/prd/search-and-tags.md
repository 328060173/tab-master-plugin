# 搜索 + 标记（自定义 Tag）交互方案

> Status: Draft · Author: Product Manager · Date: 2026-06-29

## 1. 背景与目标

### 现状与痛点
- **搜索现状**：用户反馈当前搜索框「可以」，无需大改
- **标记现状**：当前标记按钮缩在搜索框右侧，点击弹出浮层进行筛选/管理，用户觉得「有点奇怪」
- **空间问题**：侧边栏很窄（300-450px），横向空间稀缺
- **空状态问题**：用户希望标记另起一行展示，但初始没有标记时单独占一行很奇怪
- **高频功能**：标记是用户预期的高频功能，需要更高的视觉权重和操作效率

### 目标
- 保留现有搜索框的体验不变
- 给标记更高的视觉权重，让高频操作更便捷
- 优雅解决空状态问题
- 在窄侧边栏内高效展示多个标记
- 搜索与标记筛选可以叠加使用（AND 关系）

### 成功指标
- 标记功能的使用率提升 50%
- 用户完成标记筛选的操作步数从 3 步（点按钮→选标记→确认）降到 1 步（直接点标记）
- 新用户首次创建标记的转化率提升 30%

## 2. 用户场景与故事

### 用户画像
- **重度用户**：打开 50+ 标签页，习惯用标记分类（工作/学习/生活/待办）
- **中度用户**：偶尔用标记，有 3-5 个常用标记
- **新用户**：还没创建过任何标记，需要引导

### 用户故事
1. **作为**重度用户，**我想**在界面上直接看到所有标记并点击筛选，**以便**快速切换查看不同分类的标签
2. **作为**中度用户，**我想**快速给新标签添加已有标记，**以便**保持标签分类的一致性
3. **作为**新用户，**我想**看到清晰的引导来创建第一个标记，**以便**开始使用标记功能
4. **作为**任何用户，**我想**在搜索时同时用标记过滤结果，**以便**精准找到目标标签

### 关键路径
1. **新建标记**：用户有标签想分类 → 点击「+ 添加标记」→ 输入标记名称 → 确认
2. **筛选标记**：用户想查看某类标签 → 点击对应标记 chip → 列表仅显示带该标记的标签
3. **组合筛选**：用户搜索关键词 + 点击标记 → 列表显示同时满足两个条件的标签
4. **管理标记**：用户想编辑/删除标记 → 点击「更多」下拉 → 在浮层中操作

## 3. 竞品参考

### 微信收藏（主要参考）
**交互模式**：
- 顶部是搜索框，搜索框下方是横向滚动的标签列表
- 标签可点击筛选，点击后高亮显示
- 标签列表左起固定有「全部」标签，点击清除筛选
- 标签管理（添加/编辑/删除）在二级页面

**可借鉴**：
- 搜索与标签分层布局（搜索在上，标签在下）
- 标签横向排列，点击即筛选的高效交互
- 标签选中状态的视觉反馈

**不适用于我们**：
- 微信收藏是全屏宽度，标签横向滚动体验好；我们侧边栏太窄，横向滚动会很难用
- 微信收藏标签管理在二级页面，层级太深；我们需要更便捷的入口

### Toby / OneTab / Session Buddy
**交互模式**：
- Toby：标签分组（Collection）在侧边栏，点击分组筛选标签
- OneTab：保存的标签分组展示，支持简单的搜索
- Session Buddy：会话列表 + 搜索框

**可借鉴**：
- 标记/分组与搜索的 AND 关系
- 标记旁显示标签数量的信息

## 4. 交互设计

### 信息架构
```
┌─────────────────────────────┐
│  搜索框（保持不变）         │ ← 第 1 行：搜索
├─────────────────────────────┤
│  [标记行]                   │ ← 第 2 行：标记（有标记时显示）
│  [添加标记引导]             │ ← 第 2 行：引导（无标记时显示）
├─────────────────────────────┤
│  工具栏                    │
├─────────────────────────────┤
│  标签列表                  │
└─────────────────────────────┘
```

### 核心设计方案

#### 4.1 整体布局：搜索与标记分层
**决策**：分开两行，搜索在上，标记在下
- **理由 1**：搜索是低频到中频的操作，标记是高频筛选操作，分层符合「先搜索后筛选」或「先筛选后搜索」的自然流程
- **理由 2**：参考微信收藏的成熟模式，用户学习成本低
- **理由 3**：给标记足够的视觉权重，独立一行更醒目

#### 4.2 标记行的三种状态

**状态 1：空状态（无任何标记）**
- 不显示空行（避免浪费空间）
- 在搜索框下方显示一个轻量引导：「+ 添加标记来分类标签」
- 点击引导区域 → 展开输入框新建标记

**状态 2：少量标记（一行能放下）**
- 左起显示「全部」chip（点击清除所有标记筛选）
- 然后横向排列标记 chips
- 每个 chip 显示「标记名(数量)」
- 最右侧显示「+」按钮（添加新标记）
- 点击标记 chip → 切换该标记的选中状态（高亮显示）

**状态 3：标记溢出（一行放不下）**
- 左侧排列能放下的标记 chips
- 最后一个位置显示「▼ 更多(3)」（数字表示剩余标记数）
- 点击「更多」→ 向下展开浮层显示所有标记
- 浮层内保留完整的管理功能（编辑/删除/多选）

#### 4.3 标记 Chip 交互
- **点击**：切换选中状态（选中 → 高亮蓝底白字；未选中 → 灰底黑字）
- **悬停**：显示 tooltip（完整标记名 + 点击切换筛选）
- **选中状态**：右侧显示小「×」，点击可快速取消该标记筛选

#### 4.4 更多下拉浮层
复用现有 `TagFilterPanel` 组件的能力，调整布局适配：
- 显示所有标记（包含已显示在外面的）
- 支持多选标记筛选
- 支持添加/编辑/删除标记
- 点击浮层外区域自动关闭

#### 4.5 添加标记流程
- 方式 1：点击引导区 → 展开输入框 → 输入 → 确认
- 方式 2：点击「+」按钮 → 在当前位置展开输入框 → 输入 → 确认
- 方式 3：在「更多」浮层内点击「添加」→ 输入 → 确认

#### 4.6 搜索与标记的关系
**决策**：AND 关系
- 搜索关键词过滤标题/URL，标记筛选过滤带标记的标签
- 两个条件同时满足才会显示
- 示例：搜索「文档」+ 选中标记「工作」→ 显示带「工作」标记且标题/URL 含「文档」的标签

#### 4.7 聚焦模式下的处理
- 聚焦模式下，标记行**不显示**
- 理由：聚焦模式是让用户专注于少数标签，不需要筛选功能

### 交互流程

#### 流程 1：点击标记筛选
```
用户点击标记 chip
    ↓
该标记变为选中状态（蓝底白字 + 右侧 ×）
    ↓
列表过滤显示仅带该标记的标签
    ↓
（可选）用户点击另一标记 → 同时选中两个（AND 关系）
```

#### 流程 2：取消标记筛选
```
方式 A：点击标记 chip 右侧的 × → 取消该标记筛选
方式 B：再次点击标记 chip → 切换为未选中
方式 C：点击「全部」chip → 清除所有标记筛选
```

#### 流程 3：添加新标记
```
用户点击「+」按钮
    ↓
在标记行末尾展开输入框（占位）
    ↓
用户输入标记名称（最多 15 字）
    ↓
按回车或点击「确认」→ 标记创建成功并显示在末尾
    ↓
（可选）用户可立即将该标记应用到标签
```

#### 流程 4：打开「更多」浮层管理
```
用户点击「▼ 更多(3)」
    ↓
向下展开浮层，显示所有标记
    ↓
用户可：
  - 多选标记进行筛选
  - 点击「+ 添加」创建新标记
  - 悬停显示编辑/删除按钮进行管理
  - 点击「筛选」应用多选结果
  - 点击「关闭」或点击外部关闭浮层
```

---

### 边界状态处理

#### 边界 1：无任何标记
- **处理**：不显示空行，显示轻量引导「+ 添加标记来分类标签」
- **引导样式**：浅灰底，居中文字，点击整个区域都可触发添加

#### 边界 2：标记非常多（>10 个）
- **处理**：一行只放前 N 个（根据宽度动态计算），其余收进「更多」
- **浮层**：增加最大高度和滚动条，支持查看所有标记

#### 边界 3：搜索无结果 + 标记筛选无结果
- **处理**：显示统一的空状态「没有找到匹配的标签」
- **提示**：可建议「清除搜索关键词」或「取消标记筛选」

#### 边界 4：聚焦模式
- **处理**：整个标记行（包括引导区域）都不显示
- **理由**：聚焦模式是让用户专注于当前标签，不需要筛选功能

---

### 引导与教育
- **首次使用引导**：用户创建第一个标记后，显示轻量 tooltip 提示「点击标记可筛选标签」
- **Tooltip**：悬停在标记 chip 上时，显示提示「点击切换筛选」
- **空状态文案**：清晰说明标记的用途「添加标记来分类标签」

## 5. 数据模型

### 复用现有数据结构（无需变更）
- `customTags: string[]` —— 所有自定义标记列表
- `tabTagsMap: Record<string, string[]>` —— 标签 ID 到标记列表的映射
- `activeTagFilters: string[]` —— 当前激活的筛选标记

### 新增状态
- `showTagRowGuide: boolean` —— 是否显示添加标记引导（仅在 `customTags.length === 0` 时为 true）
- `showAddTagInput: boolean` —— 是否显示新建标记输入框
- `newTagName: string` —— 新建标记的输入值

## 6. 接口契约

无需新增接口，复用现有能力：
- `addCustomTag(tag: string)` —— 添加标记
- `removeCustomTag(tag: string)` —— 删除标记
- `renameCustomTag(oldTag: string, newTag: string)` —— 重命名标记
- `updateTabTags(id: number, tags: string[])` —— 更新标签的标记

## 7. 性能/安全/兼容

### 性能
- 标记行使用 CSS `display: none` 隐藏空状态，而不是 `v-if` 销毁，避免频繁重建
- 标记列表渲染使用 `v-for` + `key`，保证高效更新
- 计算 `tabCountByTag` 使用 `computed` 缓存

### 安全
- 标记名称输入限制 15 字符，防止超长
- 标记名称不支持 HTML，防止 XSS（纯文本渲染）
- 复用现有 `PopoverManager` 管理浮层，保证 z-index 层级正确

### 兼容
- Chrome 88+ / Edge 88+（与项目整体一致）
- 支持暗色模式（复用现有 `.dark` 类）
- 支持字号缩放（标记 chip 内文字使用相对单位）
- 支持卡片密度切换（标记行高度自适应）

## 8. 验收标准

### 功能验收
- [ ] 无标记时，显示「+ 添加标记来分类标签」引导区域
- [ ] 有标记时，标记行显示：「全部」+ 标记 chips +「+」
- [ ] 标记过多一行放不下时，最后显示「▼ 更多(N)」
- [ ] 点击标记 chip，该标记变为选中状态（蓝底白字 + 右侧 ×），列表筛选生效
- [ ] 再次点击标记 chip 或点击 ×，取消该标记筛选
- [ ] 点击「全部」，清除所有标记筛选
- [ ] 点击「+」按钮，在当前位置展开输入框，可创建新标记
- [ ] 点击「更多」，展开浮层显示所有标记，支持多选/添加/编辑/删除
- [ ] 搜索与标记筛选可叠加使用（AND 关系）
- [ ] 聚焦模式下，标记行不显示

### 视觉验收
- [ ] 标记行高度适中，不占用过多纵向空间
- [ ] 标记 chip 间距合理，视觉舒适
- [ ] 选中状态的高亮清晰可辨识
- [ ] 暗色模式下所有元素显示正常
- [ ] 引导区域不突兀，视觉轻量

### 交互验收
- [ ] 点击标记响应迅速，无明显延迟
- [ ] 浮层打开/关闭动画流畅
- [ ] 输入框自动聚焦
- [ ] 按 Esc 可取消新建/关闭浮层
- [ ] 点击浮层外部区域可关闭浮层

## 10. 风险与未决问题

### 风险 1：标记行占用纵向空间
- **风险**：侧边栏纵向空间本来就紧张，新增一行会让标签列表少显示 1-2 个标签
- **缓解**：标记行高度控制在 32px 以内（紧凑模式下 28px），尽量减少空间占用；无标记时不显示该行

### 风险 2：用户习惯改变
- **风险**：现有用户已经习惯点击按钮弹出浮层的方式，改为直接显示可能需要适应
- **缓解**：保留「更多」浮层，用户仍可在浮层内按旧习惯操作；不删除现有逻辑，平滑过渡

### 未决问题
- **问题**：空状态引导是常驻显示，还是只显示前 3 次？
- **暂定**：常驻显示（直到用户创建第一个标记），因为新用户可能不会一次就学会
- **后续**：根据数据看引导的点击率，如果很低再改为限时显示
